## Core 101 for JS prototypes

### The simplified mental model

1. **Objects** in JS are created in one of a few ways:
   - Using **object literal**: `{}` → internally it’s like new Object().
   - Using **array literal**: `[]`→ internally like new Array().
   - Using a **constructor function**: new Person()

2. **Every object has a hidden link** (`__proto__`) pointing to the prototype of whatever “function” created it.
   - For `{}` → `__proto__ === Object.prototype`
   - For `[]` → `__proto__ === Array.prototype`
   - For `new Person()` → `__proto__ === Person.prototype`

3. **Functions have `.prototype`**, which is the blueprint for objects created with them.

So yes:

> When you do `new Something()`, JS creates a new object, sets its `__proto__` to `Something.prototype`, and runs the function to initialize it.

```
            Function (constructor)
                   │
                   ▼
          .prototype (blueprint object)
                   │
                   ▼
new Object created
   obj.__proto__ ──┐
                   │
                   ▼
               Object.prototype
                   │
                   ▼
                  null

```

**Example with a real object:**

```js
function Person(name) {
  this.name = name;
}

Person.prototype.sayHi = function () {
  console.log("Hi, I'm " + this.name);
};

const p1 = new Person("Saugat");

p1.__proto__ === Person.prototype; // true
Person.prototype.__proto__ === Object.prototype; // true
Object.prototype.__proto__ === null; // true
```

---

- **Function** → creates objects
- **`.prototype`** → the object that new instances inherit from
- **`__proto__`** → actual link from an object to its prototype
- **`Object.prototype`** → the top of the chain
- **`null`** → end of the prototype chain
